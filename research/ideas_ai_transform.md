# AI data-transformation and e-commerce/marketing utility Actors: idea research

Date: 2026-09-28. Scope: LLM extraction, product-data enrichment, localization, content generation, PII, dedup, feed tools. Method: 25 WebSearch calls (competitor sweeps of the form `site:apify.com <keyword>` per sub-category, plus pricing/market/demand queries). Claims are tagged `[evidence: URL]` (URLs shortened, https:// omitted) or `[judgment]`.

## 0. Method, assumptions, key findings

- Search snippets did not expose competitor user counts or ratings, and WebFetch (tried once, on apify.com) was blocked by the egress proxy, so "competition" is the count of similar Actors plus any price stated in listings. No competitor's revenue or run count was verified. Every demand claim without a URL is a `[judgment]`.
- LLM cost uses Claude Haiku 4.5 ($1/M input, $5/M output tokens). Compute is assumed at roughly $0.0005-0.005 per run for a light non-browser Actor `[judgment; Apify compute-unit price not re-verified]`. Developer-paid prices below are set at 3x or more of the LLM cost (usually 5-15x). Net per event = 0.8 x price - LLM - compute.
- Reality check on the $50/month goal: at $0.03/event (net about $0.019) that is about 2,600 events/month; at $0.005/event (net about $0.0035) about 14,000 events/month. Only a few Actors with recurring B2B users will carry it `[judgment]`.
- Daily test problem for BYOK: the default input cannot contain a key, so a BYOK Actor must ship a keyless demo mode (bundled sample in, deterministic or recorded sample out) or it will fail 2 of 3 daily tests. A developer-paid Actor's daily test costs about 30 tiny LLM calls a month (roughly $0.05-0.15 per Actor) `[judgment]`. Default inputs should be bundled samples, never live third-party fetches.
- Saturated on Apify (avoid as standalone): invoice/receipt extraction (about 8 Actors), generic CSV cleaning (8+), alt-text (5+), schema.org generators (5+), Google Merchant feed validators (5-6), subtitle translation (2 direct translators, one very feature-rich, plus adjacent tools), PII redaction (4-5), product description writers (about 4, mostly URL-based).
- Gaps found: PO/ARB/.strings/.resx localization files (zero dedicated Actors in three searches), input-only review analysis (every sentiment Actor found scrapes its source), CV anonymization for blind hiring, Meta catalog fixing (one direct competitor), free-text to HS code in bulk (nine tariff Actors, but nearly all are lookup or duty-calculator tools), and anything Hebrew-specific for text processing (a dedicated Hebrew/Israel sweep found only Israeli data scrapers such as Yad2, real-estate and company-registry Actors, and no invoice, translation or Hebrew-NLP Actors [evidence: apify.com/sian.agency/yad2-property-scraper, apify.com/lentic_clockss/israel-data-search, apify.com/swerve/israel-real-estate-mcp]).
- Personal-data flags: CVs (T03, T37), bank statements (T05), IDs (T08) and medical forms (T09) are higher-risk. Reviews, tickets and contacts (T33, T34, T41) are lower-risk but should minimize names by default.

Legend. Maint. risk = chance of failing the daily test or breaking after launch (LLM dependency, bundled reference data that goes stale). Offline-testable: "yes" = deterministic, no network; "fixtures" = LLM call can be mocked with recorded responses. Score = judgment blend of gap size, recurring B2B workflow, margin, legal cleanliness, testability, Hebrew/MCP bonus; no idea scores above 8 because no demand was directly verified.

## 2. Top 20 (ranked by score, ties broken by evidence of a gap)

Ranks 1-8 are the suggested first builds; ranks 9-20 are second wave. All 20 process only user-supplied data, need no login (BYOK optional and flagged), and can finish a tiny default input in under 2 minutes. Where an LLM is involved, the default input should be 1-5 items so the daily test stays cheap and stable.

**1. T20 Software-localization file translator (score 8).** Three searches (i18n/PO, gettext, ARB/Flutter) found no Actor for PO or ARB files (.strings, .resx and XLIFF were not searched separately); only JSON/YAML (Lingo.dev Localizer) and generic translators exist, so a format-aware translator with plural and msgctxt handling and placeholder-parity validation is the clearest open lane in this category. Buyers are dev teams and agencies who re-run it every release or string freeze, the recurring batch pattern PPE rewards, and an API/MCP call from CI suits agents. LLM cost is about $0.0002-0.0003 per string-language against a $0.0015 price (5-10x), so developer-paid works with BYOK as an option for huge repos. Default input is a 5-string .po sample with placeholders and a plural form; fixtures assert placeholders survive. Risk: demand on Apify is unproven and developers can script an LLM themselves, so validation and format fidelity are the product; fold JSON/YAML (T21) in as extra formats.

**2. T33 Bring-your-own-reviews sentiment and aspect analyzer (score 8).** Every sentiment Actor found scrapes Amazon, Google Maps/Yelp or app stores; none analyzes user-supplied reviews, which is both a cleaner legal basis and an unaddressed slot. It chains after any scraper through a dataset ID, giving the pipeline value a chat window lacks (thousands of reviews under one consistent taxonomy, plus a themes/trends summary). About $0.0003 LLM per review against $0.005 (15x) leaves room to discount, and Apify's PPE docs example prices sentiment at $0.01 per post, so the price is credible. Hebrew/English mixed input is a bonus; drop reviewer names by default. Default input is 5 sample reviews; fixtures cover the LLM call.

**3. T07 Israeli tax-invoice (חשבונית מס) extractor (score 8).** The generic invoice space is saturated (about 8 Actors), but every one seen targets English-market layouts; a version tuned to Israeli statutory fields (document type, business/VAT ID, VAT lines, allocation number where present) and Hebrew/RTL text has no visible competitor. Bookkeepers repeat the job every VAT cycle, which is the recurring B2B pattern wanted, and the owner can QA Hebrew output personally. About $0.005 LLM per document (Hebrew tokenizes heavier) against $0.03 (6x); developer-paid with BYOK for high-volume users. The reform is verified: since 1 Jan 2026 B2B invoices of NIS 10,000+ (NIS 5,000+ from 1 Jun 2026, VAT excluded) need a 9-digit allocation number that the buyer needs to claim input VAT [evidence: sovos.com/regulatory-updates/vat/israel-tax-authority-confirms-accelerated-timeline-for-ctc-invoice-allocation-number/], so the lower thresholds enlarge the recurring workload.
